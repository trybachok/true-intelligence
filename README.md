# Аналитический кабинет «Истинный интеллект»

Кабинет помогает клиентам отслеживать показатели присутствия своих филиалов на геосервисах.

## Функциональные требования

### Вход и доступ к данным

- Система поддерживает вход пользователей с ролями администратора и клиента.
- Администратору доступны данные всех компаний и филиалов. Клиенту доступны только данные его компании и её филиалов.

### Аналитика и филиалы

- Дашборд показывает количество просмотров карточек, переходов на сайт, звонков и построенных маршрутов, а также среднюю оценку и количество отзывов.
- Пользователь может просмотреть список доступных филиалов, выбрать один филиал или получить сводку по всем доступным филиалам.
- Пользователь может выбрать период. Итоговые показатели и график динамики одного показателя учитывают выбранные филиалы и период.

### Расчёт показателей по отзывам

- Количество отзывов за период равно числу отзывов, опубликованных за этот период в выбранных филиалах.
- Средняя оценка за период равна среднему арифметическому оценок в той же выборке. В сводке каждый отзыв имеет одинаковый вес. Два отзыва с оценкой 5 и восемь с оценкой 4 дают среднюю оценку 4,2 и количество отзывов 10.
- При отсутствии отзывов API возвращает количество `0` и среднюю оценку `null`. Для средней оценки интерфейс показывает «Нет оценок».
- Дашборд учитывает отзывы независимо от статуса обработки.

### Получение данных и демонстрация

- Интерфейс получает данные через REST API. Система хранит пользователей, компании, филиалы, ежедневные показатели и отзывы в PostgreSQL.
- Для демонстрации подготовлены данные минимум для двух компаний, трёх филиалов и двух пользователей с разными ролями.

### Дополнительные функции

- **Модуль отзывов.** Пользователь может просматривать доступные ему отзывы и фильтровать их по рейтингу и статусу обработки.
- **Импорт статистики.** Система получает статистику из имитации внешнего API, сохраняет её в PostgreSQL и корректно обрабатывает повторные запросы.

## Нефункциональные требования

- **Безопасность.** Сервер проверяет права при каждом запросе к защищённому API, включая прямые запросы. Интерфейс показывает данные в пределах прав пользователя.
- **Надёжность хранения.** Сохранённые данные доступны после перезапуска приложения. Схема базы разворачивается миграциями.
- **Обратная связь.** Интерфейс показывает состояние загрузки и сообщает об ошибках получения данных.
- **Воспроизводимость запуска.** README содержит инструкцию по настройке окружения, запуску сервисов через Docker Compose, применению миграций, загрузке демонстрационных данных и запуску тестов.
- **Тестируемость.** В проекте есть минимум два автоматизированных теста. Как минимум один проверяет изоляцию данных компаний через API.
- **Демонстрационные данные.** Используются только вымышленные данные. Для запуска достаточно локальной конфигурации без реальных клиентских данных, ключей внешних API и доступов заказчика.
- **Масштабирование.** До разработки функций схема PostgreSQL проектируется с учётом роста до 500 и более компаний и нескольких тысяч филиалов. При проектировании учитываются запросы по компании, филиалу и периоду. К сдаче готовится описание подхода к масштабированию.
- **Технологии.** Клиентское приложение использует React, Next.js и TypeScript. Серверное приложение использует Node.js и NestJS. Образы приложений используют Node.js 26.13.1 LTS. Данные хранятся в PostgreSQL. Все сервисы запускаются только в контейнерах Docker через Docker Compose.

## Запуск и проверка

1. Из корня проекта создайте `.env` со случайным секретом JWT.

   ```bash
   if [ ! -f .env ]; then
     jwt_secret=$(openssl rand -base64 32) &&
       (umask 077; sed "s|^JWT_SECRET=.*|JWT_SECRET=$jwt_secret|" .env.example > .env)
   fi
   ```

2. Соберите и запустите контейнеры. Compose применит миграции и загрузит демонстрационные данные.

   ```bash
   docker compose --env-file .env up --build --wait
   ```

3. Проверьте подключение к базе через фронтенд. Ожидаемый ответ — `{"status":"ok"}`.

   ```bash
   curl -fsS http://localhost:3010/api/health
   ```

4. Откройте [кабинет](http://localhost:3010/) и войдите как `admin@example.test` с паролем `admin`. Установите период **26.10.2026–24.11.2026**. Проверьте, что в списке восемь компаний. Выберите «Север», затем «Центральный» и проверьте, что показатели и график обновились.
5. Нажмите «Выйти» и войдите как `client@example.test` с паролем `client`. Проверьте, что доступна только компания «Север». Откройте «Отзывы», выберите рейтинг и статус, затем вернитесь к аналитике кнопкой «На главную».
6. Запустите модульные тесты.

   ```bash
   docker compose --env-file .env exec -T backend npm test
   ```

7. Запустите HTTP-тесты, включая проверку изоляции компаний.

   ```bash
   docker compose --env-file .env exec -T backend npm run test:e2e -- --maxWorkers=1
   ```

## Вход и доступ к данным

| Роль | Email | Пароль |
| --- | --- | --- |
| Администратор | `admin@example.test` | `admin` |
| Клиент | `client@example.test` | `client` |

Демонстрационный набор содержит 8 компаний, 60 филиалов, 20 пользователей, 60 отзывов и 1 800 строк ежедневной статистики за 26 октября — 24 ноября 2026 года. Дополнительные пары пользователей имеют адреса `admin@demo-N.example.test` и `client@demo-N.example.test`, где `N` — номер от 2 до 10. Пароли этих учётных записей — `admin` и `client` соответственно.

`POST /api/auth/login` принимает email и пароль и выдаёт JWT на 15 минут. Для запросов к спискам компаний и филиалов передавайте заголовок `Authorization: Bearer <token>`. Сервер перечитывает роль и компанию из PostgreSQL при каждом защищённом запросе. Хеши scrypt из существующей базы заменяются на bcrypt при успешном входе.

## Аналитический дашборд

После входа выберите период и при необходимости компанию и филиал. По умолчанию дашборд показывает последние 30 календарных дней по UTC. Сводка и график загружаются из `GET /api/analytics`. Если фильтр филиала не задан, сводка охватывает все филиалы в выбранной области доступа.

## Демонстрационный импорт статистики

Администратор может отправить `POST /api/statistics/imports` с JSON-полями `branchId`, `from` и `to`. Имитация источника возвращает воспроизводимые значения за дни с 26 октября по 24 ноября 2026 года включительно. За пределами этого интервала источник не возвращает строки. Результат импорта доступен через `GET /api/analytics`.

## Контракт API

Спецификация OpenAPI находится в `contracts/openapi.yaml`. Она описывает реализованные технические маршруты и целевой контракт кабинета. Для прикладных операций в ней указаны параметры, проверка прав, форматы ответов и ошибки.

Hey API генерирует TypeScript-клиент из контракта при сборке Docker-образа фронтенда. Compose Watch пересобирает фронтенд при изменении контракта. Для генерации клиента локально после установки зависимостей выполните из корня проекта следующую команду.

```bash
npm --prefix frontend run generate:api
```

## Техническое описание

### Архитектура и структура

Проект организован как монорепозиторий с отдельным веб-клиентом и модульным монолитом на NestJS. Вся серверная логика работает в одном приложении и использует общую PostgreSQL. Модули разделены по предметным областям, поэтому правила доступа, построение отчётов и импорт можно развивать независимо в рамках одного процесса и одной схемы данных.

| Каталог | Назначение |
| --- | --- |
| [frontend/app](frontend/app) | Next.js App Router, форма входа, аналитика на `/` и отзывы на `/reviews`. React хранит состояние сессии и фильтров. |
| [backend/src](backend/src) | REST API и модули `auth`, `companies`, `analytics`, `reviews` и `statistics`. Контроллеры проверяют входные данные и вызывают сервисы. |
| [backend/test](backend/test) | Сквозные HTTP-тесты на Vitest и Supertest. Модульные тесты находятся рядом с кодом. |
| [db/migrations](db/migrations) | Миграции TypeORM для схемы PostgreSQL и демонстрационного набора. |
| [contracts/openapi.yaml](contracts/openapi.yaml) | Контракт REST API, из которого Hey API генерирует операции и типы для фронтенда. |

### Запросы и доступ к данным

Браузер вызывает сгенерированный клиент Hey API. Запросы идут на `/api/*` по адресу кабинета, а Next.js проксирует их в NestJS по `BACKEND_URL`. При смене фильтров React отменяет предыдущий запрос. Дашборд сохраняет текущие показатели и график на экране до загрузки нового отчёта.

После входа браузер хранит JWT в памяти и передаёт его в заголовке `Authorization`. NestJS проверяет токен и загружает актуальные роль и компанию из PostgreSQL. Сервер применяет область доступа к каждому защищённому запросу. Администратор может читать данные всех компаний, клиент — своей компании. Попытка запросить чужой филиал напрямую получает HTTP 403. Право запускать импорт есть у администратора.

### PostgreSQL, отчёты и импорт

Компании связаны с филиалами, филиалы — с отзывами и ежедневными метриками. У клиента есть ссылка на компанию, а одна строка статистики соответствует паре «филиал, дата». Схема задаёт первичные и внешние ключи, ограничения и индексы. TypeORM управляет подключением, транзакциями и миграциями. Сервисы передают данные в SQL через параметры.

PostgreSQL сначала ограничивает отчёт доступными филиалами, затем агрегирует метрики по дням и отдельно рассчитывает средний рейтинг и количество отзывов. Границы периода определяются по UTC. Дни без статистики отображаются на графике с нулевым числом просмотров. Список отзывов фильтруется на сервере и загружается страницами по курсору идентификатора.

Импорт получает данные через подменяемый источник, проверяет ответ целиком и сохраняет строки одной транзакцией. Повторный импорт той же даты для филиала обновляет существующую запись через `ON CONFLICT`. Поэтому повторный запрос сохраняет одну запись на день, а ошибка записи откатывает всю пачку.

### Развёртывание и ограничения

Docker Compose запускает PostgreSQL с постоянным томом. Сервис миграций применяет схему и загружает демоданные до запуска API. Фронтенд запускается после успешной проверки API. HTTP-тесты покрывают вход, разграничение доступа, расчёты, отзывы и повторный импорт. NestJS Observe подключается при наличии обоих ключей мониторинга в окружении.

Сессия действует 15 минут. После обновления вкладки или истечения токена требуется новый вход. Источник импорта имитирует внешнее API и возвращает данные за 26.10.2026–24.11.2026. Импорт запускается через REST API.

На фронтенде не реализовано сохранение состояния фильтров и сессии, поэтому при перезагрузке сессия будет сброшена и потребуется повторная авторизация.

### Масштабирование до 500+ компаний

На первом этапе достаточно сохранить модульный монолит. Индексы по компании, филиалу и дате поддерживают запросы кабинета. Перед ростом нагрузки стоит измерить планы запросов через `EXPLAIN (ANALYZE, BUFFERS)` и время ответа на объёме в несколько тысяч филиалов и с типичной глубиной истории.

Если общие отчёты станут узким местом, можно добавить дневные агрегаты по компаниям и обновлять их после импорта. Для сохранения корректного среднего рейтинга в агрегате следует хранить сумму оценок и число отзывов. Если импорт начнёт конкурировать с чтением за ресурсы, его можно перенести в отдельный обработчик очереди, сохранив транзакционную запись и ключ «филиал, дата».
